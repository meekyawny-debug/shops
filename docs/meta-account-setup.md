## 1. Create Meta Business Account

You will create **one** Meta Business Account that owns all three brands. Each brand gets its own Facebook Page, Instagram account, Ad Account, and Pixel underneath this umbrella.

### Steps

1. Go to [business.facebook.com](https://business.facebook.com/).
2. Click **Create Account**.
3. Enter the following details:
   - **Business name:** `Shops Media Group` (or your legal entity name)
   - **Your name:** Your full legal name
   - **Business email:** A shared email such as `meta@yourcompany.com`
4. Click **Submit**.
5. Check your email inbox and click the **confirmation link** from Meta.
6. Once confirmed, you will land on the **Business Settings** dashboard at:
   ```
   https://business.facebook.com/settings/
   ```
7. Complete business verification if prompted:
   - Go to **Security Center** in Business Settings.
   - Upload a business document (business license, utility bill, or bank statement).
   - This is required before you can run ads at scale.

> **Tip:** Use a business email with a custom domain (not Gmail/Yahoo). Meta trusts verified domains more during the business verification process.

> **Warning:** Do NOT create separate Business Accounts for each brand. A single Business Account can manage multiple Pages, Ad Accounts, and Pixels. Separate accounts create billing headaches and make cross-brand audience sharing impossible.

## 6. Generate Conversions API (CAPI) Access Token

The Conversions API sends server-side events directly to Meta, improving tracking reliability (especially with iOS 14.5+ restrictions and ad blockers). You need a System User and access token.

### 6a. Create a System User

1. Go to [business.facebook.com/settings/system-users](https://business.facebook.com/settings/system-users).
2. Click **Add**.
3. Fill in:
   - **System User Name:** `shops-capi-server`
   - **Role:** Select **Admin** (required for CAPI access to all Pixels).
4. Click **Create System User**.

### 6b. Assign Assets to the System User

1. Select the `shops-capi-server` system user.
2. Click **Add Assets**.
3. Under **Pixels**, assign all three Pixels:
   - `GLOWHAVEN Pixel` — Permission: **Manage Pixel**
   - `AURAE Pixel` — Permission: **Manage Pixel**
   - `NESTWELL Pixel` — Permission: **Manage Pixel**
4. Under **Pages**, optionally assign all three Facebook Pages with **Manage Page** permission.
5. Click **Save Changes**.

### 6c. Generate the Access Token

1. Select the `shops-capi-server` system user.
2. Click **Generate New Token**.
3. Select the following permissions:
   - `ads_management`
   - `ads_read`
   - `business_management`
4. Click **Generate Token**.
5. **Copy the token immediately** — it will only be shown once.
   ```
   EAAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

### 6d. Add the Token to Your Environment

Add the token to your `.env` file at the project root (`D:\shops\.env`):

```env
# Meta Conversions API (CAPI) Access Token
# System User: shops-capi-server
# Has Manage Pixel permissions on all three brand Pixels
FB_CAPI_ACCESS_TOKEN=EAAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

If each brand needs a separate token (e.g., separate system users per brand), use brand-specific variable names:

```env
# Brand-specific CAPI tokens (alternative setup)
GLOWHAVEN_FB_CAPI_ACCESS_TOKEN=EAAxxxxxxxx_glowhaven
AURAE_FB_CAPI_ACCESS_TOKEN=EAAxxxxxxxx_aurae
NESTWELL_FB_CAPI_ACCESS_TOKEN=EAAxxxxxxxx_nestwell
```

Also store the Pixel IDs alongside:

```env
# Meta Pixel IDs
GLOWHAVEN_META_PIXEL_ID=123456789012345
AURAE_META_PIXEL_ID=234567890123456
NESTWELL_META_PIXEL_ID=345678901234567
```

> **Warning:** Never commit the `.env` file to version control. Ensure `.env` is listed in your `.gitignore`. The CAPI access token has full control over your Pixels and ad accounts.

> **Tip:** System User tokens do not expire unless you manually revoke them. Set a calendar reminder to rotate the token every 6-12 months as a security best practice.

## 7. Verify Domain for Each Brand

Domain verification proves to Meta that you own the domains your stores operate on. This is required for Aggregated Event Measurement (AEM) and gives you priority in configuring conversion events.

### Option A: Meta Tag Verification (Recommended)

This is the fastest method. Add a `<meta>` tag to the `<head>` of each store's homepage.

#### 7a. Get the Verification Meta Tags

1. Go to [business.facebook.com/settings/owned-domains](https://business.facebook.com/settings/owned-domains).
2. Click **Add > Create a New Domain**.
3. Enter the domain for GLOWHAVEN:
   ```
   glowhaven.yourstore.com
   ```
4. Meta will give you a meta tag like:
   ```html
   <meta name="facebook-domain-verification" content="abcdef1234567890abcdef1234567890" />
   ```
5. Repeat for AURAE and NESTWELL:
   ```
   aurae.yourstore.com
   nestwell.yourstore.com
   ```

#### 7b. Add Meta Tags to the Storefront

In the storefront app layout (`apps/storefront/app/[storeSlug]/layout.tsx`), add the domain verification meta tag dynamically based on the store slug:

```tsx
// Example: domain verification meta tags per store
const domainVerificationTags: Record<string, string> = {
  glowhaven: "abcdef1234567890abcdef1234567890",
  aurae: "fedcba0987654321fedcba0987654321",
  nestwell: "112233445566778899aabbccddeeff00",
};

// In the <head> of the layout:
<meta
  name="facebook-domain-verification"
  content={domainVerificationTags[storeSlug]}
/>
```

#### 7c. Verify

1. Deploy the changes (or run the storefront locally and use a tunnel like ngrok).
2. Return to the domain settings in Business Settings.
3. Click **Verify** on each domain.
4. Meta will crawl the page and confirm the meta tag is present.

### Option B: DNS TXT Record Verification

Use this if you cannot modify the HTML `<head>` easily or if you use a custom domain per store.

1. In the domain verification screen, select **DNS Verification**.
2. Meta will give you a TXT record value like:
   ```
   facebook-domain-verification=abcdef1234567890abcdef1234567890
   ```
3. Add this TXT record in your DNS provider:

   | Domain | Record Type | Host | Value |
   |---|---|---|---|
   | `glowhaven.yourstore.com` | TXT | `@` | `facebook-domain-verification=abcdef...` |
   | `aurae.yourstore.com` | TXT | `@` | `facebook-domain-verification=fedcba...` |
   | `nestwell.yourstore.com` | TXT | `@` | `facebook-domain-verification=112233...` |

4. Wait for DNS propagation (can take up to 72 hours, usually under 1 hour).
5. Return to Business Settings and click **Verify**.

> **Tip:** If your stores are subdomains under a single root domain (e.g., `yourstore.com`), you only need to verify the root domain once. Subdomains are automatically covered.

## 8. Set Up Events Manager

Events Manager is where you monitor and debug all events sent by the Meta Pixel (browser-side) and the Conversions API (server-side). Confirm that both are sending events and deduplicating correctly.

### 8a. Open Events Manager

1. Go to [facebook.com/events_manager](https://www.facebook.com/events_manager/).
2. In the left sidebar, select the **Data Source** (Pixel) you want to inspect:
   - `GLOWHAVEN Pixel`
   - `AURAE Pixel`
   - `NESTWELL Pixel`

### 8b. Verify Pixel (Browser-Side) Events

1. Select a Pixel (e.g., **GLOWHAVEN Pixel**).
2. Click the **Test Events** tab.
3. Enter your storefront URL:
   ```
   https://glowhaven.yourstore.com
   ```
4. Click **Open Website**. A new browser tab will open with your storefront.
5. Perform the following actions on the storefront:
   - Load the homepage (should fire `PageView`).
   - View a product page (should fire `ViewContent`).
   - Add an item to the cart (should fire `AddToCart`).
   - Go to checkout (should fire `InitiateCheckout`).
   - Complete a test purchase (should fire `Purchase`).
6. Return to the **Test Events** tab. You should see each event listed with:
   - **Source:** `Browser` (from the Pixel).
   - **Status:** Green checkmark.

### 8c. Verify CAPI (Server-Side) Events

1. Stay in the **Test Events** tab for the same Pixel.
2. Repeat the same storefront actions.
3. You should see duplicate entries for each event:
   - One with **Source: Browser** (from Meta Pixel JavaScript).
   - One with **Source: Server** (from Conversions API).
4. Both should show a green checkmark.

### 8d. Verify Deduplication

Deduplication ensures Meta counts each real-world event only once, even if both the Pixel and CAPI report it.

1. Go to the **Overview** tab for the Pixel.
2. Look at the event count chart. Events should not be double-counted.
3. In the **Test Events** tab, matched Browser + Server events should show a **"Deduplicated"** badge.
4. Deduplication requires that both the Pixel and CAPI send the same `event_id` for each event. In your storefront code, ensure:
   ```tsx
   // Generate a unique event ID for each user action
   const eventId = crypto.randomUUID();

   // Send via Pixel (browser)
   fbq('track', 'AddToCart', { content_ids: [productId] }, { eventID: eventId });

   // Send via CAPI (server) — use the same eventId
   fetch('/api/meta-capi', {
     method: 'POST',
     body: JSON.stringify({
       event_name: 'AddToCart',
       event_id: eventId,
       // ... other parameters
     }),
   });
   ```

> **Warning:** If you see events from **Server** only and no **Browser** events, the Meta Pixel script is not loading (likely blocked by ad blockers). This is expected for some users — CAPI provides the fallback. If you see **Browser** only and no **Server** events, the CAPI integration is broken — check your `FB_CAPI_ACCESS_TOKEN` and server logs.

### 8e. Repeat for All Brands

Repeat steps 8a through 8d for each Pixel:
- **AURAE Pixel** at `https://aurae.yourstore.com`
- **NESTWELL Pixel** at `https://nestwell.yourstore.com`

## 9. Configure Standard Events

Map your storefront tracking events to Meta's standard events for optimal ad optimization and reporting.

### 9a. Event Mapping

| Storefront Action | Meta Standard Event | When It Fires | Key Parameters |
|---|---|---|---|
| Any page load | `PageView` | Every page view | None (automatic) |
| Product page view | `ViewContent` | User views a product detail page | `content_type`, `content_ids`, `content_name`, `value`, `currency` |
| Add to cart | `AddToCart` | User clicks "Add to Cart" | `content_type`, `content_ids`, `content_name`, `value`, `currency`, `num_items` |
| Begin checkout | `InitiateCheckout` | User reaches checkout page | `content_ids`, `num_items`, `value`, `currency` |
| Purchase complete | `Purchase` | Order confirmation page loads | `content_ids`, `content_type`, `value`, `currency`, `num_items`, `order_id` |

### 9b. Pixel (Browser-Side) Implementation

Add the Meta Pixel base code to your storefront layout. The following belongs in `apps/storefront/app/[storeSlug]/layout.tsx`:

```tsx
// Meta Pixel base code — loads on every page
<Script id="meta-pixel" strategy="afterInteractive">
  {`
    !function(f,b,e,v,n,t,s)
    {if(f.fbq)return;n=f.fbq=function(){n.callMethod?
    n.callMethod.apply(n,arguments):n.queue.push(arguments)};
    if(!f._fbq)f._fbq=n;n.push=n;n.loaded=!0;n.version='2.0';
    n.queue=[];t=b.createElement(e);t.async=!0;
    t.src=v;s=b.getElementsByTagName(e)[0];
    s.parentNode.insertBefore(t,s)}(window, document,'script',
    'https://connect.facebook.net/en_US/fbevents.js');
    fbq('init', '${store.metaPixelId}');
    fbq('track', 'PageView');
  `}
</Script>
```

Then fire events at the appropriate moments:

```tsx
// Product page — ViewContent
useEffect(() => {
  if (typeof window !== 'undefined' && window.fbq) {
    const eventId = crypto.randomUUID();
    window.fbq('track', 'ViewContent', {
      content_type: 'product',
      content_ids: [product.id],
      content_name: product.name,
      value: product.price,
      currency: 'USD',
    }, { eventID: eventId });

    // Send same event server-side via CAPI
    sendCapiEvent('ViewContent', eventId, { productId: product.id, value: product.price });
  }
}, [product]);

// Add to Cart button handler
function handleAddToCart() {
  const eventId = crypto.randomUUID();
  window.fbq('track', 'AddToCart', {
    content_type: 'product',
    content_ids: [product.id],
    content_name: product.name,
    value: product.price,
    currency: 'USD',
    num_items: 1,
  }, { eventID: eventId });

  sendCapiEvent('AddToCart', eventId, { productId: product.id, value: product.price });
}

// Checkout page — InitiateCheckout
useEffect(() => {
  if (typeof window !== 'undefined' && window.fbq) {
    const eventId = crypto.randomUUID();
    window.fbq('track', 'InitiateCheckout', {
      content_ids: cartItems.map(item => item.productId),
      num_items: cartItems.length,
      value: cartTotal,
      currency: 'USD',
    }, { eventID: eventId });

    sendCapiEvent('InitiateCheckout', eventId, { value: cartTotal, items: cartItems });
  }
}, []);

// Order confirmation — Purchase
useEffect(() => {
  if (typeof window !== 'undefined' && window.fbq) {
    const eventId = crypto.randomUUID();
    window.fbq('track', 'Purchase', {
      content_type: 'product',
      content_ids: order.items.map(item => item.productId),
      value: order.total,
      currency: 'USD',
      num_items: order.items.length,
      order_id: order.id,
    }, { eventID: eventId });

    sendCapiEvent('Purchase', eventId, { orderId: order.id, value: order.total });
  }
}, []);
```

### 9c. CAPI (Server-Side) Implementation

Create a server-side endpoint or utility to send events to Meta's Conversions API:

```tsx
// Example: apps/storefront/src/lib/meta-capi.ts

const META_CAPI_URL = 'https://graph.facebook.com/v21.0';

interface CapiEvent {
  event_name: string;
  event_id: string;
  event_time: number;
  event_source_url: string;
  action_source: 'website';
  user_data: {
    client_ip_address?: string;
    client_user_agent?: string;
    fbc?: string;  // Facebook click ID from _fbc cookie
    fbp?: string;  // Facebook browser ID from _fbp cookie
    em?: string;   // Hashed email
    ph?: string;   // Hashed phone
  };
  custom_data?: {
    content_ids?: string[];
    content_type?: string;
    value?: number;
    currency?: string;
    num_items?: number;
    order_id?: string;
  };
}

export async function sendServerEvent(
  pixelId: string,
  event: CapiEvent
): Promise<void> {
  const accessToken = process.env.FB_CAPI_ACCESS_TOKEN;

  if (!accessToken || !pixelId) {
    console.warn('Meta CAPI: Missing access token or pixel ID');
    return;
  }

  const url = `${META_CAPI_URL}/${pixelId}/events?access_token=${accessToken}`;

  const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      data: [event],
    }),
  });

  if (!response.ok) {
    const error = await response.text();
    console.error(`Meta CAPI error for pixel ${pixelId}:`, error);
  }
}
```

### 9d. Configure Aggregated Event Measurement (AEM)

After domain verification (Step 7), configure your event priority in Events Manager:

1. Go to **Events Manager** > select a Pixel.
2. Click **Aggregated Event Measurement** in the sidebar.
3. Click **Configure Web Events** for the verified domain.
4. Set up to **8 prioritized events** (highest priority first):

   | Priority | Event | Optimization |
   |---|---|---|
   | 1 | `Purchase` | Highest value — optimize campaigns for purchases |
   | 2 | `InitiateCheckout` | Fallback for users who reach checkout |
   | 3 | `AddToCart` | Mid-funnel signal |
   | 4 | `ViewContent` | Product interest signal |
   | 5 | `PageView` | Broadest signal |

5. Click **Apply** and confirm.
6. Repeat for each brand's domain.

> **Warning:** After changing AEM configuration, there is a **72-hour instrumentation period** where data may be delayed. Do not make changes during active ad campaigns if possible.

## Troubleshooting

### Pixel Not Firing
- Confirm the Pixel ID in the store config matches exactly (no extra spaces).
- Check that the Meta Pixel `<script>` tag is in the `<head>`, not the `<body>`.
- Verify with the Meta Pixel Helper extension — it shows a blue icon with a number when events are detected.
- Check the browser console for JavaScript errors blocking the Pixel script.

### CAPI Events Not Appearing
- Verify `FB_CAPI_ACCESS_TOKEN` is set and the server has restarted after the change.
- Check server logs for HTTP errors from the `graph.facebook.com` API.
- Test the token in the [Graph API Explorer](https://developers.facebook.com/tools/explorer/) with a manual event send.
- Ensure the System User has **Manage Pixel** permission on the correct Pixel.

### Events Not Deduplicating
- Both Pixel and CAPI events must send the exact same `event_id` string.
- The `event_id` must be generated **once** per user action and shared between browser and server calls.
- Events must arrive within a **5-minute window** of each other to be matched.

### Domain Verification Failing
- For meta tag: ensure the tag is in the `<head>` and the page is publicly accessible (not behind auth).
- For DNS: confirm the TXT record has propagated using [MXToolbox](https://mxtoolbox.com/TXTLookup.aspx).
- Clear Meta's cache by clicking **Verify** again after 24 hours.

### Ad Account Spending Limit Reached
- Go to **Payment Settings** and increase or remove the spending limit.
- New accounts may also have Meta-imposed daily limits that increase over time with consistent spend.
